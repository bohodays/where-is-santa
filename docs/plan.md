# 산타 어디쯤 기획서

> 원본은 Claude Docs의 "산타 어디쯤 기획서"이고, 이 파일은 저장소에서 AI와 사람이 함께 참고하기 위한 사본이다.
> 기획이 바뀌면 원본과 이 파일을 같이 고친다. 마지막 정리: 2026-11-06

## 개요

크리스마스이브에 누구나 링크 하나로 산타의 현재 위치와 우리 동네 도착 시각을 보는 웹 서비스 '산타 어디쯤'(where-is-santa)을 만들고, 12월 24일에 공개한다.

- **목적:** 기획, 디자인, 구현, 테스트, 자동화 전 과정에 AI를 활용하고, AI를 어떻게 통제하고 검증했는지 기록으로 남긴다.
- **핵심 장면:** 이브 밤에 가족, 연인, 친구가 한 화면을 같이 보며 "산타가 서울까지 2시간 남았대"라고 말하는 순간.
- **타겟:** 남녀노소 모두. 아이부터 어르신까지 설명 없이 쓸 수 있어야 한다.
- **공개일:** 2026년 12월 24일. 회고와 정리는 12월 31일까지.

## 설계 원칙

링크를 열면 3초 안에 산타가 보이고, 누구나 설명 없이 쓸 수 있어야 한다.

- **로그인 없음:** 가입 단계는 아이와 어르신 모두를 이탈시킨다. 모든 기능을 비로그인으로 제공한다.
- **3초 안에 이해:** 첫 화면에는 지도 위 산타와 우리 동네 도착까지 남은 시간, 두 가지만 둔다.
- **모바일 우선:** 이브 밤에는 대부분 메신저로 받은 링크를 폰으로 연다. 모바일에서 초기 로딩 2.5초 이내(LCP)를 목표로 한다.
- **접근성:** WCAG 2.2 AA 기준. 큰 글씨 모드, 고대비, 스크린리더용 산타 위치 안내 문구, 애니메이션 줄이기 설정 존중.
- **개인정보 최소화:** 동네 선택과 편지 내용은 브라우저에만 저장한다. 만 14세 미만 사용자 정보를 서버로 보내지 않는다.

## 화면 구성

메인 화면 하나에 모든 기능이 바텀시트로 열리는 단일 페이지 구조다. 페이지 이동이 없어야 어르신도 길을 잃지 않는다. 화면 시안은 claude.ai 디자인 캔버스 "산타 어디쯤 화면 시안"에 있다.

- **메인 지도:** 세계 지도 위 산타 아이콘과 지나온 경로(실선), 남은 경로(점선). 상단에 "지금 산타는 ○○ 상공" 한 줄, 하단에 도착 카운트다운 카드.
- **동네 선택 시트:** 시·구 단위 검색(초성 검색 지원). 위치 권한은 선택 사항으로만 요청.
- **공유 시트:** 공유 카드 미리보기, 인사말 입력, 링크 복사. 공유받은 링크는 받는 사람의 동네 기준으로 열린다.
- **데모 모드:** 12월 24일이 아닐 때 "크리스마스이브로 시간 이동" 버튼. 시간 흐름 배속(실제, 1초=1분, 1초=10분) 선택.
- **편지 시트(여유 있으면):** 편지 쓰기, 썰매에 실리는 애니메이션, 내가 쓴 편지 보관함.
- **설정:** 큰 글씨, 고대비, 애니메이션 줄이기, 소리 켜기.

## 산타 위치 규칙

산타는 "막 12월 25일 자정이 된 곳"에 있다. 자정은 시계가 아니라 해 기준으로 본다.

    도착 시각(UTC) = 12월 25일 00:00 UTC − 보정 경도 ÷ 15시간

- 시계 기준 자정을 쓰면 같은 시간대 도시(서울·부산·도쿄)에 동시에 도착하고, 중국처럼 넓은 시간대에서 경로가 앞뒤로 튄다.
- 해 기준이면 동쪽부터 몇 분씩 차례로 도착한다. 도쿄 23:41 → 오사카 23:58 → 부산 00:24 → 서울 00:32 (한국 시각).
- **날짜변경선 보정:** `utcOffset × 15 − 경도`가 180보다 크면 경도 +360, −180보다 작으면 −360. 키리바시·사모아가 맨 앞에 온다. 첫 도착은 한국 시각 12월 24일 오후 7시대.
- **현재 위치:** `santaAt(현재 시각, 경로표)`로 직전 도시와 다음 도시를 찾고, 두 도시 사이 대권 경로에서 진행률만큼의 지점에 그린다. 도시마다 30초 머문다.
- **기기 시계 보정:** 처음 접속할 때 서버 응답 시각과 비교해 보정값을 둔다.
- **데모 모드:** '현재 시각'만 바꾼다. 테스트도 같은 원리로 아무 시각이나 재현한다.

## 기술 포인트

가장 깊게 다루는 주제는 시간대 기반 경로 계산이다. 나머지는 성능과 공유 경험을 다듬는 포인트다.

- **시간대 기반 경로 시뮬레이션:** 위 규칙을 서버 없이 순수 함수로 계산해, 같은 시각이면 모든 기기에서 같은 위치가 나오게 한다.
- **경계 사례 테스트:** 날짜변경선 양쪽 국가, 30분·45분 단위 시간대(인도, 네팔), 넓은 단일 시간대(중국 카슈가르)를 테스트로 고정한다.
- **지도 애니메이션 성능:** 산타 이동은 requestAnimationFrame으로 보간하고, 지도는 MapLibre GL로 렌더링한다. 저사양 폰에서도 60fps 목표.
- **공유 카드 이미지:** OG 이미지를 서버에서 동적으로 생성해 메신저 링크 미리보기에 도착 시각이 보이게 한다.
- **이브 밤 트래픽 대비:** 정적 배포와 CDN 캐시로 서버 부하 없이 버틴다.
- **PWA 도착 알림(여유 있으면):** 웹 푸시로 도착 30분 전 알림. iOS는 홈 화면 추가 후에만 동작한다는 제약을 안내한다.

### 경로 데이터 만드는 순서

1. GeoNames에서 도시를 받아 인구·대륙별 균형으로 300~500개를 고른다. 국내는 시군구 데이터를 따로 합친다.
2. 도시마다 12월 25일 기준 UTC 오프셋을 구하고, 위 규칙으로 보정 경도와 도착 시각을 계산한다.
3. 도착 시각 순으로 정렬해 `route.json`(도시명, 좌표, 오프셋, 도착 UTC)을 만든다. 한글 도시명은 AI로 번역하고 주요 도시는 직접 검수한다.
4. 클라이언트는 `santaAt(현재 시각)`으로 산타를 그린다.

## AI 활용 계획

어필 포인트는 "AI로 만들었다"가 아니라 "AI를 어떻게 통제하고 검증했다"다. 단계마다 검증 방법과 남길 증거를 미리 정해둔다.

| 단계   | AI가 하는 일                             | 사람이 검증하는 방법                                              | 남길 증거                     |
| ------ | ---------------------------------------- | ----------------------------------------------------------------- | ----------------------------- |
| 기획   | 요구사항 문서, 화면 목록 초안            | 설계 원칙과 대조해 범위 확정                                      | 이 기획서와 변경 이력         |
| 디자인 | 시안 3안, 디자인 토큰, 아이콘·일러스트   | 대비율 검사, 실제 폰 화면에서 확인                                | 시안 비교 이미지, 토큰 파일   |
| 구현   | Claude Code로 기능 구현                  | 코드 규칙 문서(CLAUDE.md)로 구조·금지 사항 고정, PR마다 직접 리뷰 | 규칙 문서와 개정 이력         |
| 테스트 | 단위·E2E 테스트, 타임존 엣지 케이스 생성 | 일부러 버그를 넣어 테스트가 잡는지 확인                           | 커버리지 수치, 잡은 버그 목록 |
| 자동화 | GitHub Actions CI·배포, AI PR 리뷰       | AI 리뷰 지적 중 맞은 것과 틀린 것 기록                            | 워크플로 파일, 리뷰 적중률    |
| 기록   | 주간 작업 로그 정리                      | AI가 틀렸던 사례와 고친 방법을 직접 작성                          | 회고 블로그 글, README        |

매주 `docs/ai-log.md`에 "AI가 잘한 것 / 틀린 것 / 고친 방법 / 줄어든 시간" 네 줄을 남긴다.
