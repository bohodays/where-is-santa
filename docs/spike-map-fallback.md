# 지도 장애 대응 시험

**결정 (2026-11-10): A + B.** 지도는 없어도 서비스가 돌아가게 한다.

- **A. 글자 먼저:** 카운트다운과 "지금 산타는 ○○" 글자를 먼저 보여주고, 지도 JS는 화면이 뜬 뒤 따로 불러온다(동적 import). 지도 JS를 못 불러오면 글자만 남긴다.
- **B. 자체 윤곽 지도:** OpenFreeMap 스타일·타일이 실패하거나 응답이 없으면 Natural Earth 육지 윤곽(정적 파일)으로 바꾼다.
- **보류:** 기획서의 대안이던 PMTiles 자체 호스팅. `pmtiles` 의존성, 저장소 계정, 이브 밤 트래픽 비용이 필요하다. 이 서비스는 세계 전체를 보는 낮은 확대 수준이 대부분이라 윤곽 지도로 충분하다고 판단했다.

시험 코드는 main에 넣지 않았다. 태그 `archive/spike-map-fallback`(커밋 `6626f45`)의 `src/components/spike/FallbackMapSpike.tsx`에 있다. 시험 브랜치는 지웠다.

## 윤곽 지도 데이터

| 항목 | 내용 |
|---|---|
| 원본 | [Natural Earth](https://www.naturalearthdata.com/) `ne_110m_land` v5.1.2 ([nvkelso/natural-earth-vector](https://github.com/nvkelso/natural-earth-vector)) |
| 이용 조건 | 퍼블릭 도메인. 상업적 이용 가능, 출처 표시 의무 없음([이용 조건](https://www.naturalearthdata.com/about/terms-of-use/)). 화면 출처에는 "Made with Natural Earth"를 적는다 |
| 크기 | 92KB, gzip 28KB (좌표 소수 둘째 자리) |
| 만드는 법 | `npx -y mapshaper@0.7.97 -i ne_110m_land.geojson -o public/maps/ne_110m_land.json format=geojson precision=0.01` |

중간 해상도(`ne_50m_land`)는 단순화해도 gzip 89KB라서 쓰지 않았다.

## 전환 규칙 (시험 코드 기준, 3주차 본 구현에서 다시 조정)

| 상황 | 감지 | 결과 |
|---|---|---|
| 지도 JS를 못 불러옴 | 동적 import 실패 | 글자만, "지도를 불러오지 못했어요. 산타 소식은 위에서 계속 볼 수 있어요." |
| 스타일을 못 불러옴 | 스타일을 읽기 전 `error` 이벤트(sourceId 없음) | 윤곽 지도 |
| 타일만 실패 | `error` 이벤트(sourceId 있음) 3번 | 윤곽 지도 |
| 응답 없음 | 지도를 만든 뒤 10초 안에 스타일을 못 읽음 | 윤곽 지도 |

## 측정 (2026-11-10, PC Chrome 156 헤드리스, 화면 412×900, 데모 모드)

Chrome DevTools Protocol로 요청을 막거나(차단) 멈춰 두고(응답 없음) 확인했다.

| 상황 | 지도 상태 | 카운트다운 표시 | 전환 시각 |
|---|---|---|---|
| 1. 정상 | 타일 지도 | 0.3초 | 타일 지도 준비 2.6~3.1초 |
| 2. OpenFreeMap 전체 차단 | 윤곽 지도 | 0.3초 | 0.14~0.2초 |
| 3. 타일(.pbf)만 차단 | 윤곽 지도 | 0.3초 | 0.7초 |
| 4. OpenFreeMap 응답 없음 | 윤곽 지도 | 0.3초 | 10.1초 |
| 5. 지도 JS 청크 차단 | 글자만 | 0.3초 | - |

- 모든 상황에서 카운트다운이 0.3초 안에 먼저 보였다.
- 동적 import로 나눈 결과, 시험 화면 첫 로드 JS는 108kB다(지난 시험 화면은 397kB). 지도 JS(약 1.1MB, 압축 전)는 별도 청크로 나중에 받는다.

## 시험하며 알게 된 것

1. **워커 요청은 따로 막아야 한다.** MapLibre는 지도 조각(타일)을 워커에서 받는다. 페이지에만 차단을 걸었더니 타일이 정상으로 받아져 "타일만 실패" 시험이 통과하지 못했다. 화면을 보고 시험 방법의 문제임을 알았고, 워커에도 차단을 걸어 다시 확인했다(`Target.setAutoAttach`).
2. **응답 없음 기준(10초)은 느린 망과 맞춰 봐야 한다.** 지난 시험에서 느린 4G 첫 방문에 지도가 다 그려지기까지 8.2초였다. 이 10초는 스타일을 읽는 시간만 재므로 다르지만, 본 구현 때 느린 4G에서 정상 지도가 윤곽 지도로 잘못 바뀌지 않는지 확인한다.
3. **윤곽 지도로 바뀌면 OpenFreeMap 출처 표기가 사라진다.** 윤곽 지도에는 "Made with Natural Earth"를 넣는다(의무는 아님).
4. **스프라이트·글꼴 실패도 스타일 오류로 잡힐 수 있다.** 그 경우에도 윤곽 지도로 바뀌므로 서비스에는 문제가 없지만, 본 구현 때 오류 종류를 구분할지 정한다.
